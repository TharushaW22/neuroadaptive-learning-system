# EEG engine output contract (for the fusion, XAI and cueing components)

**Schema version 1.0.0.** Machine-readable: [`output_contract.schema.json`](output_contract.schema.json)
(JSON Schema, generated from `src/eegengine/inference/schema.py`). A real example produced by
the engine: [`output_example.json`](output_example.json). Both are regenerated by
`python scripts/export_contract.py`. The live API also serves them: `GET /schema`, `GET /contract/sample`.

## When outputs are produced
One `CognitiveStateOutput` per **analysis window of 4 s, every 2 s** (50 % overlap). The first output
appears after 4 s of signal. Windows are indexed from 0 (`window_index`) and timed both in ISO 8601
UTC (`timestamp_start`, `timestamp_end`) and in seconds since the session start (`t_start_s`, `t_end_s`).

How to receive them:
* **WebSocket** `ws://<host>:8000/stream/{subject}/{condition}?model=<id>&speed=1` — replay of a STEW
  recording. Messages: `{"type": "meta", ...}` once, then for each window `{"type": "raw", ...}`
  (display signal) followed by `{"type": "state", "output": <CognitiveStateOutput>}`, and `{"type": "end"}`.
* **HTTP** `POST /predict` (multipart: `file` = STEW-format text or JSON `{"data": [[...]]}` with
  14 rows = channels; optional `model`, `participant_id`, `session_id`) → a JSON list of outputs.
* **Python** `CognitiveEngine(model).push(chunk)` → list of outputs (pydantic objects; `.model_dump()`).

## Fields

| Field | Type | Meaning |
|---|---|---|
| `schema_version` | string | contract version; minor bumps only add fields |
| `participant_id`, `session_id` | string | identifiers passed in by the caller |
| `window_index` | int | 0, 1, 2, … |
| `timestamp_start`, `timestamp_end` | ISO 8601 string | window edges in UTC |
| `t_start_s`, `t_end_s` | float | window edges in seconds since session start |
| `signal_quality.overall` | 0–1 | 1 − fraction of channels failing a quality check in this window |
| `signal_quality.flag` | `good` \| `warn` \| `bad` | `good`: no bad channel; `warn`: blinks or ≤ 2 bad channels; `bad`: more. **Consumers should down-weight or ignore `bad` windows.** |
| `signal_quality.bad_channels` | list | channels failing a check now |
| `signal_quality.interpolated_channels` | list | persistently bad channels rebuilt by spherical-spline interpolation |
| `states.workload.label` | string | argmax of the smoothed probabilities |
| `states.workload.probabilities` | {class: p} | calibrated, EMA-smoothed probabilities (sum to 1) |
| `states.workload.raw_probabilities` | {class: p} | this window only, no smoothing |
| `states.workload.confidence` | 0–1 | max smoothed probability |
| `states.workload.source` | `"model"` | a trained, cross-validated model |
| `states.workload.model_version`, `.task` | string | which model / which label definition |
| `states.attention / fatigue / readiness.value` | float | EMA-smoothed **heuristic index** |
| `….raw_value` | float | this window only |
| `….source` | `"heuristic_index"` | **not a trained prediction** (STEW has no labels for these states) |
| `….formula`, `….note` | string | how the index is computed |
| `band_power` | {channel: {band: µV²}} | absolute band power, bands delta 1–4, theta 4–8, alpha 8–13, beta 13–30, gamma 30–45 Hz |
| `connectivity` | {metric, band, channels, matrix} | 14 × 14 phase-locking value matrix of the window (default band alpha) |
| `latency_ms` | float | processing time of the window on the server |

### Workload classes
`task` tells consumers which label set is in use:
* `workload_binary` → classes `low`, `high` (trained on rest vs SIMKAP multitasking; T1)
* `workload_within_task` → classes `moderate`, `high` (trained on self-rated workload during the task; T3)

### Heuristic indices (exact formulas, `src/eegengine/inference/heuristics.py`)
* attention = engagement index β / (α + θ), summed band power over all 14 channels (Pope et al., 1995)
* fatigue = (θ + α) / β over P7, P8, O1, O2 (Jap et al., 2009)
* readiness = 0.5 · E/(1+E) + 0.5 · 1/(1+F), with E = attention, F = fatigue — a transparent 0–1
  combination chosen for the dashboard, **not** a validated measure.

They are ratios, so their scale differs between people: compare a value with the same person's
earlier values (or their rest baseline), not with a fixed threshold.

## Smoothing
`value_t = α · x_t + (1 − α) · value_{t−1}` with α = 0.4 by default (`ema_alpha`), applied to the workload
probabilities and to the three indices. `raw_*` fields expose the unsmoothed values.

## Stability promise
Fields are never removed or renamed within a major version. New optional fields may be added.
When attention/fatigue/readiness models are trained on the team-collected data, their `source` will
change to `"model"` and they will gain `label`/`probabilities` like `workload` — consumers should
branch on `source`.
