# EEG Neuro-Cognitive Understanding Engine (J26-DS-333, Component 1)

Part of *Neuroadaptive Learning System Using EEG, Computer Vision, and Agentic AI* (SLIIT IT4010).

A reproducible Python engine that turns 14-channel Emotiv EEG into calibrated cognitive-state
estimates every 2 seconds, with a FastAPI backend (REST + WebSocket) and a React dashboard.

```
EEG acquisition → signal quality → preprocessing → epoching → features (spectral, entropy, wavelet,
PLV, coherence, graph) → classical baselines + hybrid CNN-LSTM-Transformer-GAT → calibrated
probabilities → timestamped JSON (docs/output_contract.md) → dashboard / fusion / XAI / cueing
```

> **Label honesty.** STEW provides **workload** labels only. Attention, fatigue and learning
> readiness are reported as established EEG band-power indices, marked
> `source: "heuristic_index"` — *not trained predictions*. Their model heads exist (masked) and can be
> trained once the team-collected labelled data is available (see below).

How to read it: T1 separates rest from the SIMKAP multitasking test, which differs in more than
workload (eye/hand movement, arousal). T3 compares moderate vs high self-rated workload *within* the
task — the confound-free test. T2 (rating level) is almost the rest/task split and mostly
re-measures T1 (see `docs/labels.md`). Normalising features with the subject's own rest recording
raises T1 scores substantially; it is reported separately (`results/summary_classical.md`).

## Setup

```powershell
cd component1
py -3.13 -m venv .venv                    # Python 3.11+ works
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m pip install -e .
cd frontend; npm install; cd ..
```

### Linux / macOS
```bash
cd component1
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt && .venv/bin/pip install -e .
```

Put the STEW files in `data/raw/STEW/` (`sub01_lo.txt` … `sub48_hi.txt`, `ratings.txt`). The raw and
processed data are git-ignored.

## Commands
Run from `component1/` with the venv's Python (`.venv\Scripts\python` on Windows, `.venv/bin/python` on Linux).

| Step | Command | Output |
|---|---|---|
| **Everything, in order** | `python scripts/run_all.py` (`--quick` skips the long runs, `--from <step>` resumes) | all below |
| Dataset EDA | `python scripts/explore_dataset.py` | `results/eda/` |
| Raw signal quality | `python scripts/run_quality.py` | `results/quality/` |
| Preprocess + epoch | `python scripts/run_preprocess.py [--config preprocess_2s.yaml] [--ica-demo]` | `data/processed/epochs_<hash>.npz`, `results/preprocessing/`, `docs/labels.md` |
| Features | `python scripts/run_features.py` | `data/processed/features_<hash>.parquet`, `results/features/` |
| Classical baselines (LOSO) | `python scripts/run_baselines.py` · `--config experiments/classical_rest.yaml` · `--config experiments/classical_kfold5.yaml` | `results/cls_*` |
| Feature ablation + Wilcoxon | `python scripts/run_ablation.py` | `results/cls_*_A*`, `results/stats_classical.json` |
| Deep models (5-fold) | `python scripts/run_deep.py --smoke` then `python scripts/run_deep.py` | `results/deep_*`, `results/logs/` |
| Deep statistics | `python scripts/deep_stats.py` | `results/stats_deep.json` |
| Deployable models | `python scripts/train_final_classical.py` · `python scripts/run_deep.py --final A10_hybrid` | `models/` |
| Reports | `python scripts/export_report.py` | `results/summary*.md`, `results/summary.json`, README results |
| Output contract | `python scripts/export_contract.py` | `docs/output_contract.schema.json`, `docs/output_example.json` |
| Leakage audit | `python scripts/audit_leakage.py` | `results/leakage_audit.json` |
| Demo snapshot | `python scripts/export_demo.py` | `frontend/public/demo/` |
| Tests | `python -m pytest` | |

Every experiment is driven by a YAML file in `configs/` and writes `metrics.json`, `folds.csv`,
`predictions.csv`, `confusion_matrix.png` and a copy of its config to `results/<experiment_id>/`.
Seeds are fixed (42).

## Running the API and the dashboard
```powershell
# terminal 1 — API on http://localhost:8000 (docs at /docs)
.venv\Scripts\python -m uvicorn api.main:app --port 8000

# terminal 2 — dashboard on http://localhost:5173
cd frontend; npm run dev
```
The dashboard detects the API automatically. Without the API it switches to **demo mode** and
replays the bundled snapshot (`frontend/public/demo/`), so it also works fully offline — e.g.
`npm run build` then open `frontend/dist/` with any static server (`npx vite preview`).
Header toggles: Demo / Live API, Projector (larger text), Light / Dark.

Docker (optional): `docker compose up --build` → API on :8000, dashboard on :5173 (needs `data/` and `models/`).

## Plugging in the team-collected Emotiv data
1. **Signals** — one text file per recording, same format as STEW: whitespace-separated, no header,
   one row per sample, 14 columns in the Emotiv order `AF3 F7 F3 FC5 T7 P7 O1 O2 P8 T8 FC6 F4 F8 AF4`,
   values in µV (the DC offset is fine), 128 Hz. Name them `<participant>_<session>.txt`.
   Other channel orders or rates: pass `ch_names` / `fs` to `CognitiveEngine`, and adapt
   `io/stew.py` (`CHANNELS`, `FS`) for training.
2. **Labels** — a CSV with one row per labelled time span:
   ```csv
   participant,session,t_start_s,t_end_s,workload,attention,fatigue,readiness
   P01,S1,0,120,low,high,low,high
   P01,S1,120,300,high,high,medium,medium
   ```
   Empty cells = no label (masked). Each epoch takes the label of the span that contains its centre.
3. **Train** — build the metadata columns `y_attention`, `y_fatigue`, `y_readiness` like `labels.py`
   does for workload, set their masks to the labelled rows, and the hybrid's masked multi-task loss
   trains those heads automatically (`models/deep/hybrid.py → masked_multitask_loss`). Keep
   subject-wise CV (`training/cv.py`).
4. **Deploy** — once those heads are validated, the engine should emit them with `source: "model"`
   (see `docs/output_contract.md`, "Stability promise").
